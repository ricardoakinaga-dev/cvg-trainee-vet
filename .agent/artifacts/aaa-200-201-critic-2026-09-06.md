# AAA-200/201 — crítica independente e reteste local

## Crítica inicial

O agente independente `Carver` fez leitura somente, sem editar arquivos nem
executar runtime, e rejeitou a aprovação local (`REJECT`, severidade `P1`). A
crítica encontrou:

1. a resposta do endpoint de assignment devolvia `diagnosticResultId`,
   `assignmentId` e `moduleId`, contrariando o contrato `0561`;
2. replay de assignment existente não falhava fechado quando
   `sourceDiagnosticResultId` pertencia a outro resultado;
3. vínculo de atividade existente não falhava fechado quando apontava para
   outro assignment;
4. PostgreSQL/RLS live, concorrência real, rollback e release permaneciam sem
   evidência, independentemente do foco local.

## Correção aplicada

- `adaptiveCurriculumAssignmentProjectionSchema` passou a aceitar somente
  `availableAt`, `status`, `version` e `blockReason` por item, sem IDs ou
  módulos internos;
- `publicAdaptiveAssignmentProjection` passou a construir explicitamente essa
  projeção redigida;
- a persistência agora rejeita source diagnostic diferente e vínculo de
  atividade apontando para assignment diferente;
- testes HTTP, contrato e persistência foram atualizados antes do reteste.

## Reteste

Com os artefatos TypeScript locais recompilados:

```text
corepack pnpm exec vitest run --project unit \
  packages/contracts/src/learning-state.test.ts \
  apps/api/src/http.test.ts \
  packages/persistence/src/adaptive-assignment-repository.test.ts
```

Resultado: `3` arquivos / `96` testes PASS.

## Releitura pós-correção

Foi solicitada nova leitura ao mesmo agente. O retorno foi `REVISE`: o agente
declarou que, sob a restrição de não executar comandos nessa segunda chamada,
não conseguiu confirmar os arquivos atuais nem emitir aprovação independente.
Isso não invalida o reteste local executado pelo lead, mas mantém a revisão
independente pós-correção como gap explícito; não é registrada como `PASS`.

## Limites

Este artefato registra a correção local do P1; a nova leitura independente,
integração PostgreSQL/RLS live, browser → API → PostgreSQL, produção, clínica,
piloto e release continuam gates separados.
